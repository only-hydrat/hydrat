# Обновления из панели Hydrat

В разделе «Система» можно проверить и установить новый релиз Hydrat.
Шлюз и контроллер обновляются вместе. Версии Xray, Tor и Lyrebird входят в
образ релиза. Служба на хосте запускает Docker, а панель подключается к ней
через Unix-сокет.

Главный `docker-compose.yml` входит в тот же образ, что и Hydrat. Перед
установкой служба проверяет, что действующий файл совпадает с файлом из
текущего опубликованного образа, и подготавливает Compose из нового образа.
Настройки из `.env` и локальные overrides применяются при проверке.
При сбое служба восстанавливает прежний Compose вместе с образами и данными.

Для первого перехода со старого образа без встроенного Compose установите
релиз с этим файлом вручную по [руководству по эксплуатации](../docs/operations.md).
Это также относится к локальным сборкам и изменённому основному файлу.
Отдельные изменения `docker-compose.updates.yml` и `docker-compose.i2p.yml`
требуют ручного обновления. Если I2P уже включён и его Compose-файл совпадает в
обоих релизах, служба сохраняет работающий контейнер I2P.

## Подключение на Linux с systemd

Понадобится Hydrat с командой `updater`, Docker Engine, Compose v2 и обычная
структура данных из `config/config.yml`. Для установки используется тот же
набор файлов Compose, с которым запущен проект. В примере ниже проект находится
в `/srv/hydrat`. Редактировать Compose-файлы и `.env` должны только доверенные
администраторы хоста.

1. Извлеките `/usr/local/bin/hydrat` из доверенного образа Hydrat или соберите
   бинарник из того же коммита, что и установленные контейнеры.
   Собирайте его в своём каталоге, затем установите в каталог root.

   ```sh
   CGO_ENABLED=0 go build -trimpath -o ./hydrat-updater ./cmd/hydrat
   sudo install -m 0755 ./hydrat-updater /usr/local/sbin/hydrat-updater
   sudo install -m 0644 updates/hydrat-updater.service /etc/systemd/system/
   ```

2. Создайте `/etc/hydrat-updater.conf` от имени root.

   ```ini
   HYDRAT_UPDATER_PROJECT=/srv/hydrat
   HYDRAT_UPDATER_FILES=docker-compose.yml,docker-compose.updates.yml
   ```

   Для I2P добавьте `docker-compose.i2p.yml` перед
   `docker-compose.updates.yml` в обеих конфигурациях. Сохраните свой порядок
   существующих файлов и overrides. Директория проекта, файл `.env` и значения
   `COMPOSE_PROJECT_NAME` должны совпадать с уже работающей установкой.

3. Запустите службу и добавьте в `.env` проекта последовательность файлов для
   обычных команд `docker compose`. Последним идёт файл, которым управляет
   установщик.

   ```sh
   sudo systemctl daemon-reload
   sudo systemctl enable --now hydrat-updater
   ```

   ```dotenv
   COMPOSE_FILE=docker-compose.yml:docker-compose.updates.yml:/var/lib/hydrat-updates/compose.json
   ```

   Выполните из каталога проекта `docker compose up -d --no-build controller`.
   Проверьте «Система → Обновления» после входа. Для использования обновлений
   установленные образы Hydrat должны иметь метку
   `org.opencontainers.image.version`. Готовые образы из GHCR содержат её.
   Служба проверяет команду запуска, пути Xray и Tor, конфиги Xray, файл
   применённого плана и SQLite в работающих контейнерах. Для нестандартной
   схемы используйте ручное обновление. Перед установкой служба сверяет
   монтирования в запущенных контейнерах с Compose. Если, например, `DATA_DIR`
   был изменён после запуска, установка прервётся до остановки сервисов.
   На время операции служба сохраняет итоговую конфигурацию Compose
   в файле с правами `0600` и использует её для отката. Не редактируйте
   содержимое смонтированных файлов конфигурации во время обновления.

На время обновления шлюз и контроллер перезапускаются. WireGuard-соединения
могут прерваться, а в панель потребуется войти заново. Служба проверяет пути
хранилищ и запуск встроенных компонентов. Если релиз меняет монтирования,
сети, именованные тома или дополнительные сервисы, примените его вручную.
Сохраните `.env`, локальные overrides и пользовательские настройки.

Служба проверяет `/api/ready` до установки и десять раз подряд после запуска.
Если проверка не проходит до установки, обновление откладывается. При неудачной
установке служба восстанавливает прежний Compose, образы, базу и применённый
план. Когда старые контейнеры запустились, служба снимает режим обслуживания.
Если маршруты ещё не прошли проверку,
служба периодически повторяет проверку готовности и возвращает кнопки
обновления после успеха. Перезапуск службы на этом этапе продолжит проверку
без повторной загрузки снимка.
Для диагностики используйте
`journalctl -u hydrat-updater`. Предыдущие образы `hydrat-rollback:*`, копии
данных `update-*.db` и `applied-plan.update-*.json` сохраняются для ручного
восстановления. Управляемый override и журнал незавершённой установки находятся
в `/var/lib/hydrat-updates`.

При ручном переходе на другой релиз учитывайте, что сохранённый в
`compose.json` образ имеет приоритет над `HYDRAT_IMAGE` из `.env`.
Перед изменением override сохраните его копию и проверьте, что в каталоге
службы нет журнала незавершённой операции `pending.json`.
