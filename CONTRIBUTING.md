# Участие в разработке Hydrat (Contributing)

Мы рады вкладу сообщества в развитие Hydrat! Пожалуйста, ознакомьтесь с данным руководством перед отправкой изменений.

---

## Стек технологий и требования

- **Go**: 1.26+
- **Сетевой стек**: WireGuard, Xray-core, Tor, nftables
- **Контейнеризация**: Docker & Docker Compose
- **ОС**: Linux (ядро 5.10+ с поддержкой nftables и WireGuard)

---

## Процесс разработки

### 1. Подготовка окружения
Клонируйте репозиторий и загрузите зависимости:
```bash
git clone https://github.com/only-hydrat/hydrat.git
cd hydrat
go mod download
```

### 2. Запуск тестов
Перед внесением изменений убедитесь, что все существующие тесты проходят:
```bash
go test ./...
```

Для запуска тестов с подробным выводом:
```bash
go test -v ./...
```

### 3. Форматирование и проверка кода
Код должен быть отформатирован в соответствии со стандартами Go и не содержать замечаний линтера:
```bash
gofmt -s -w .
go vet ./...
```

### 4. Коммиты
Мы придерживаемся формата [Conventional Commits](https://www.conventionalcommits.org/):
- `feat:` новая функциональность
- `fix:` исправление ошибки
- `refactor:` рефакторинг кода без изменения логики
- `docs:` изменения в документации
- `test:` добавление или исправление тестов
- `chore:` рутинные задачи, обновление зависимостей

Пример:
```
feat(routing): add fallback latency threshold for active outbounds
```

---

## Отправка изменений (Pull Request)

1. Создайте отдельную ветку для задачи:
   ```bash
   git checkout -b feat/my-feature
   ```
2. Реализуйте изменения, добавьте тесты для новой функциональности.
3. Убедитесь, что `go test ./...` и `go vet ./...` завершаются без ошибок.
4. Создайте Pull Request в ветку `main`, подробно заполнив предоставленный шаблон.
5. Дождитесь прохождения автоматических проверок (CI) и код-ревью.
