# Доступ к .onion

В панели откройте **Клиенты → Доступ к .onion через Tor** у нужного устройства. Настройка выключена по умолчанию и доступна только администратору. Пользователь видит статус в «Моём подключении», а инструкции — в разделе «Доступ к .onion» без входа администратора.

«Ожидает применения» означает, что разрешение сохранено, но ещё не применено шлюзом. «Маршрут готов» означает наличие применённого Tor-маршрута, а не проверку конкретного сайта. «Нет готового Tor-маршрута» требует проверки Tor-пула. При отключении дождитесь статуса «Выключен»; до применения изменения показывается «Отключается».

Поддерживаются публичные v3-адреса, их поддомены и TCP. UDP, onion v2 и сервисы с клиентской авторизацией не поддерживаются. Недоступный onion-сайт не является основанием для исключения всего Tor-профиля. При отказе профиля выбирается другой готовый профиль; существующие соединения потребуют повторного открытия.

## Браузеры

Инструкция в кабинете находится в разделе «Система». Кнопка «Как открыть .onion» в «Моём подключении» открывает её сразу.

### Android: Firefox Nightly

1. В Hydrat включите «Доступ к .onion через Tor» у своего клиента. Если нет прав, попросите администратора. Включите WireGuard и дождитесь статуса «Маршрут готов».
2. Откройте Firefox Nightly от Mozilla: в обычном Firefox для Android доступ к `about:config` ограничен.
3. В адресной строке откройте `about:config`, найдите `network.dns.blockDotOnion` и переключите значение на `false`.
4. В настройках Firefox найдите «DNS через HTTPS» и выберите «Выкл.», чтобы использовался DNS VPN.
5. Если в Android задан сторонний «Частный DNS» (Private DNS), временно отключите его. В конфигурации WireGuard сохраните DNS Hydrat — обычно `10.44.0.1`.
6. Откройте полный адрес с `http://` или `https://` перед `.onion`, чтобы браузер не отправил его в поиск. Адрес берите с официального сайта сервиса. Прокси настраивать не нужно.
7. Для возврата установите `network.dns.blockDotOnion=true` и восстановите прежние настройки DNS. Доступ можно выключить в Hydrat.

Для Chrome, Edge, Brave и других браузеров Android нет подтверждённой настройки доступа через Hydrat. Для описанного способа откройте Firefox Nightly.

### Другие устройства

| Устройство и браузер | Действия |
| --- | --- |
| Firefox, Windows/macOS/Linux | Включите WireGuard и доступ в Hydrat. В `about:config` установите `network.dns.blockDotOnion=false`. Отключите DNS через HTTPS и сохраните DNS WireGuard. Откройте полный onion-адрес с официального сайта сервиса. |
| Chrome, Edge, Brave, Safari на компьютере | Проверенной универсальной настройки нет: браузер может блокировать onion-адрес до DNS-запроса. Для доступа через Hydrat используйте Firefox по инструкции выше. |
| iPhone/iPad | Подтверждённой инструкции для прямого доступа через Hydrat пока нет. Настройки Firefox для Android и компьютера не применимы к iOS. Обычные сайты работают через WireGuard. |

Не отключайте проверку TLS-сертификатов. Инструкции основаны на документации; все сочетания реальных устройств и браузеров отдельно не тестировались.

## Как это устроено

Шлюз отвечает на `.onion` локально и только разрешённому клиенту, назначая постоянный виртуальный IPv4 из `198.18.0.0/15`. Такие DNS-запросы, включая AAAA и HTTPS/SVCB, не уходят внешнему резолверу. DNS остальных доменов обслуживает прежний dnsmasq через внутренний `127.0.0.1:1053`.

Таблица загружается в работающие Tor-профили через приватный Unix ControlSocket с cookie-аутентификацией (`MAPADDRESS`). Готовность для onion публикуется после восстановления таблицы, в том числе при переводе исследовательского профиля в рабочий. Для каждого клиента создаётся отдельная SOCKS-идентичность; обычные назначения TCP/UDP сохраняются. Правила виртуального диапазона выполняются до GeoRules и direct. При отсутствии разрешения или маршрута диапазон блокируется. Внешние SOCKS/Control-порты открывать не нужно.

Это удобный доступ к сайтам, а не замена Tor Browser: обычный браузер сохраняет свой отпечаток, cookies и другие особенности. Администратор шлюза может прочитать onion-имена из локальной таблицы; она не шифруется и защищена правами `0600`. Сами имена не записываются в журналы DNS этого модуля.

## Состояние и восстановление

Рядом с `applied-plan.json` хранятся `onion-mappings.json`, `.initialized` и файл блокировки `.lock`. Сохраняйте таблицу и маркер вместе с данными шлюза/WireGuard; **`hydrat backup` сохраняет SQLite, но не эти файлы**. Для согласованной резервной копии остановите gateway и скопируйте его каталог состояния. Не удаляйте таблицу и не восстанавливайте старую копию, пока устройства могут использовать новые закэшированные адреса.

Адреса не переиспользуются для других имён. Таблица ограничена 1024 именами. При заполнении, повреждении или потере таблицы новый onion-доступ закрывается; обычный DNS продолжает работать. Восстановите актуальную копию состояния. Не удаляйте маркер для обхода защиты. WireGuard-подсеть не должна пересекаться с `198.18.0.0/15`.

Источники: [DNS Firefox](https://support.mozilla.org/kb/firefox-dns-over-https), [настройки Firefox](https://searchfox.org/firefox-main/source/modules/libpref/init/StaticPrefList.yaml), [MAPADDRESS](https://spec.torproject.org/control-spec/commands.html#mapaddress).

Для новых имён действует лимит на клиента: всплеск до 8 запросов и восстановление одного разрешения за 6 секунд; общий лимит — всплеск 16 и одно разрешение в секунду. Уже выданные адреса не расходуют этот бюджет. Медленный Tor не занимает очередь обычного DNS.

Разработчики могут запустить `scripts/test-onion-integration.sh` на Linux с Docker и Go. Скрипт загружает фиксированную версию Tor Chutney, собирает тестовый образ и создаёт изолированную сеть Tor и два WireGuard-клиента в контейнере без внешней сети. Требуется privileged-контейнер; запускайте на машине для разработки. Контейнер и временные данные удаляются автоматически.

Обычные DNS-запросы передаются dnsmasq по UDP; при усечённом ответе повторяются по TCP. Основной и резервный onion-профили участвуют в активных проверках через очередь дополнительных проверок, не занимая зарезервированную очередь обычных primary/reserve.

## Проверка качества Tor

При включённом onion-доступе существующий QoE-контур проверяет официальные onion-сайты DuckDuckGo и Tor Project через обслуживающие Tor-профили. Проверки используют общий лимит воркеров; прямых HTTP-запросов с VPS и отдельного измерения скорости для onion нет. Результаты onion не меняют оценку обычных TCP/UDP-маршрутов.

Ошибка запроса учитывается против профиля только при свежем успешном ответе того же сервиса через независимый мост. Если оба пути не отвечают, результат остаётся неопределённым. Несколько подтверждённых ошибок или устойчиво медленных ответов ухудшают оценку через существующее окно QoE. Результат от заменённого Tor-процесса отбрасывается.

Здоровый основной профиль сохраняется, чтобы не обрывать открытые соединения. Резерв выбирается по свежим проверкам; при подтверждённом ухудшении основного доступен и третий готовый профиль. Остальные квалифицированные мосты последовательно исследуются в существующем ограниченном Tor-пуле. Все мосты одновременно не запускаются, а первая загрузка произвольного onion-сайта всё ещё может потребовать построения цепочки. Когда onion-доступ выключен у всех клиентов, эти проверки прекращаются.
