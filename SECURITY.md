# Политика безопасности (Security Policy)

Команда Hydrat уделяет повышенное внимание безопасности сетевого шлюза, защите конфиденциальности пользователей и изоляции трафика.

---

## Поддерживаемые версии

| Версия | Поддержка |
| :--- | :--- |
| `main` (текущая) | :white_check_mark: |

Критические исправления безопасности оперативно выпускаются в ветке `main`.

---

## Сообщение об уязвимости

Если вы обнаружили уязвимость безопасности в Hydrat:

1. **Не создавайте публичный Issue** с описанием уязвимости или эксплойта.
2. Отправьте отчёт через [GitHub Security Advisory](https://github.com/only-hydrat/hydrat/security/advisories/new) или по электронной почте мейнтейнеру проекта: only_hydrat@proton.me.
3. В отчёте укажите:
   - Описание проблемы и потенциальное воздействие;
   - Шаги для воспроизведения или PoC (Proof of Concept);
   - Затронутые компоненты и конфигурацию.
4. Мы ответим в течение 48 часов и согласуем сроки выпуска исправления перед публичным раскрытием.

## Архитектурные меры безопасности в Hydrat

Hydrat изначально проектируется с соблюдением принципов эшелонированной защиты (Defense-in-Depth):

- **Минимальные права на секреты**: файлы конфигурации с приватными ключами (`wg0.conf`, `.env`) создаются и читаются с правами доступа `0600`.
- **Read-only контейнеры**: контейнер контроллера запускается с корневой файловой системой в режиме только для чтения (`read_only: true`), используя изолированный `tmpfs` для временных файлов.
- **Отсутствие паролей по умолчанию**: пароль панели управления никогда не зашивается в образы или конфигурации; запуск контроллера требует обязательного явного задания надёжного пароля администратора через переменную окружения `HYDRAT_ADMIN_PASSWORD` и завершается ошибкой при его отсутствии.
- **Защита от утечки российского трафика**: модуль `disallow_ru_egress` исключает ноды выхода в РФ из квалификации для предотвращения деанонимизации и блокировки чувствительного трафика.
- **Права gateway**: gateway использует Docker capability defaults и явно добавляет `NET_ADMIN` и `NET_RAW`; контейнер не запускается в режиме `privileged`. Это не least-privilege профиль: ему нужны WireGuard, маршруты, nftables, порты и подготовка bind-mounted хранилища.
